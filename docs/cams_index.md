# Индекс базы камер (cams.idx)

Необязательный файл к `cams.bin` (формат — `cams_format.md`). Нужен, когда база читается с SD-карты и не загружается в RAM целиком: индекс держится в памяти, а записи камер подгружаются с карты только для нужных ячеек. Генератор — `tools/gen_cams_idx.py`.

## 1. Формат cams.idx

Little-endian, без выравнивания. Размер файла строго `16 + 8·(M+1)`.

### Заголовок, 16 байт

| Смещение | Тип | Значение |
|---|---|---|
| 0 | char[4] | `CIX1` — сигнатура и версия формата |
| 4 | u32 | M — число непустых ячеек |
| 8 | u32 | N — число записей в `cams.bin` |
| 12 | u32 | CRC-32 (zlib) всего файла `cams.bin` |

### Элементы, M+1 штук по 8 байт

| Смещение | Тип | Значение |
|---|---|---|
| 0 | u32 | ключ ячейки `key = (int)(lat·20)·4096 + (int)(lon·20)` |
| 4 | u32 | номер первой записи этой ячейки в `cams.bin` (с нуля) |

Элементы идут по возрастанию ключа. Последний элемент завершающий: ключ `0xFFFFFFFF`, номер равен N. Число записей в ячейке i равно `first[i+1] − first[i]`, отдельного поля нет.

Смещение записи k в `cams.bin`: `16 + 12·k`. Все записи ячейки лежат подряд, поэтому читаются одним `fseek` + `fread`.

## 2. Размер

Реальная база всей России (≈185 тыс. камер, 2,2 МБ) даёт ≈28,7 тыс. непустых ячеек, то есть индекс ≈230 КБ. Для региона (`--bbox`) — единицы или десятки килобайт.

## 3. Поиск камер вокруг точки

1. Из координат получить `cy`, `cx` и 3×3 соседних ключа `(cy+dy)·4096 + (cx+dx)`, dy, dx ∈ {−1, 0, 1}.
2. Для каждого ключа бинарный поиск по массиву элементов индекса в RAM.
3. Если ключ найден в позиции i, прочитать с карты записи `first[i] … first[i+1]−1` и обработать как обычно.

```c
typedef struct { uint32_t key, first; } idx_t;

// возвращает число записей ячейки, *first — номер первой; 0 — ячейка пуста
static uint32_t cell_find(const idx_t *ix, uint32_t m, uint32_t key, uint32_t *first) {
    uint32_t lo = 0, hi = m;                    // элементов m+1, последний — завершающий
    while (lo < hi) {
        uint32_t mid = (lo + hi) / 2;
        if (ix[mid].key < key) lo = mid + 1; else hi = mid;
    }
    if (lo >= m || ix[lo].key != key) return 0;
    *first = ix[lo].first;
    return ix[lo + 1].first - ix[lo].first;
}
// чтение: fseek(f, 16 + 12L * first, SEEK_SET); fread(buf, 12, count, f);
```

Оценка на SD по SPI: один запрос — до 9 небольших чтений по ~120 байт (1–2 сектора на ячейку), порядка 5–20 мс. Если держать в RAM окно из уже прочитанных 3×3 ячеек и обновлять его только при пересечении границы центральной ячейки (раз в несколько километров), обращений к карте почти нет. Читать лучше в отдельной задаче, а не в задаче LVGL.

## 4. Согласованность с cams.bin

Перед использованием стоит сверить `N` из индекса с `N` из заголовка `cams.bin`. CRC-32 нужен для полной проверки при обновлении базы: если `cams.bin` заменили, а `cams.idx` остался старым, значения не совпадут. Считать CRC на каждом старте не обязательно, достаточно сверять N (и дату из заголовка `cams.bin`).

## 5. Генерация

```
python3 tools/gen_cams_idx.py igo.csv                              # cams.bin + cams.idx
python3 tools/gen_cams_idx.py igo.csv speedcam_D6.bin -o cams.bin --bbox 55.0 36.5 56.3 38.5
python3 tools/gen_cams_idx.py --from-bin cams.bin                  # индекс для готового cams.bin
```

Скрипт сам вызывает `gen_cams.py` (должен лежать рядом) с теми же параметрами, затем строит индекс по итоговому `cams.bin` и проверяет, что каждая запись лежит в своей ячейке и сумма по ячейкам равна N. Файлы кладутся на SD рядом друг с другом.
