# Формат базы камер

Описаны два формата: исходный (Datakam `speedcam_*.bin`) и собственный `cams.bin`, который читает HUD. Конвертер — `tools/gen_cams.py`, чтение — `waveshare_hud_mockup/cam_alert.c`.

## 1. cams.bin (то, что лежит в FATFS как `/cams.bin`)

Little-endian, без выравнивания. Размер файла строго `16 + N·12` (OTA-страница проверяет).

### Заголовок, 16 байт

| Смещение | Тип | Значение |
|---|---|---|
| 0 | char[4] | `CAM1` — сигнатура и версия формата |
| 4 | u32 | N — число записей |
| 8 | u32 | дата базы, числом `ддммгг` (например 110926 = 11.09.26) |
| 12 | u32 | резерв, 0 |

### Запись, 12 байт

| Смещение | Тип | Значение |
|---|---|---|
| 0 | f32 | широта, ° |
| 4 | f32 | долгота, ° |
| 8 | u16 | направление камеры, ° (0..359, откуда смотрит камера по ходу контролируемого движения); `0xFFFF` — нет направления, камера работает в обе стороны |
| 10 | u8 | ограничение скорости, км/ч (0 — неизвестно; значения >255 обрезаются) |
| 11 | u8 | биты 0..3 — индекс типа; биты 4..5 — признак из исходной базы (0/1/2); биты 6..7 — 0 |

Индекс типа → код Datakam: `0:510, 1:530, 2:700, 3:710, 4:720, 5:730, 6:740, 7:750, 8:760`; `15` — код не из списка.
В `HUD_CAM_TYPE_MASK` бит i соответствует индексу типа i (бит 0 = код 510, бит 8 = код 760).

### Порядок записей

Записи отсортированы по ключу ячейки сетки 0,05° (20 ячеек на градус):

```
cy  = (int)(lat * 20)
cx  = (int)(lon * 20)
key = cy * 4096 + cx
```

Внутри ячейки порядок произвольный. Поиск: бинарный поиск первой записи с нужным ключом (`lower_bound`), затем перебор записей с этим ключом. Чтобы найти камеры вокруг машины, берутся 3×3 соседние ячейки (ячейка ≈ 5,5 км по широте, ≈ 3 км по долготе в Москве, окно оповещения ≤ 600 м). База целиком загружается в PSRAM при старте и дальше только читается.

Размер: вся Россия ≈ 185 тыс. записей ≈ 2,2 МБ; Москва и область ≈ 420 КБ.

### Как HUD использует запись

- расстояние вдоль движения > 0 и ≤ R, где R = clamp(v·12 с, 200, 600) м;
- боковое отклонение от линии движения ≤ `HUD_CAM_CROSS_M` (35 м; для уже ведомой камеры в 1,7 раза больше — гистерезис);
- если направление задано — курс машины в пределах ±`HUD_CAM_DIR_DEG` (50°) от него;
- тип проходит по маске `HUD_CAM_TYPE_MASK`; из подходящих выбирается ближайшая впереди.

## 2. Исходный формат Datakam (`speedcam_*.bin`)

Найден разбором файла; не документирован производителем, поэтому часть полей неизвестна.

### Заголовок, 68 байт

| Смещение | Значение |
|---|---|
| 0..63 | текст cp1251: `DATAKAM. MOSCOW. SPEEDCAM BASE.` / `СОЗДАН ОТ: дд.мм.гг` / пустая строка |
| 64 | u32 N — число записей |

Размер файла = `68 + N·23`.

### Запись, 23 байта

| Смещение | Тип | Значение |
|---|---|---|
| 0 | f32 | долгота |
| 4 | f32 | широта |
| 8 | u16 | код типа (510, 530, 700, 710, 720, 730, 740, 750, 760) |
| 10 | u16 | ограничение, км/ч |
| 12 | u16 | направление, ° (360 — без направления) |
| 14 | u16 | радиус оповещения, м (во всей базе 500) |
| 16 | u16 | константа 10 |
| 18 | u8 | признак 0/1/2 (смысл не установлен; переносится в cams.bin) |
| 19 | u32 | ключ сортировки Datakam; HUD не использует |

Конвертер отбрасывает записи с координатами вне 19°<lon<180°, 40°<lat<82°. Проверено по реальным логам: курс машины при проезде записи совпадает с её направлением.

### Что известно о кодах типов

Сверка с размеченным списком (≈1270 точек, совпадение до 30 м):

| Код | Что это |
|---|---|
| 510 | стационарная камера (в том числе муляжи МЛЖ, ММ, ДПСкам — идут тем же кодом) |
| 760 | пост ДПС / ДПС мобильный |
| 700, 710, 720 | не камеры скорости: объекты с короткой зоной ≈50 м, предположительно неровности / переезды (не подтверждено) |
| 530 | всего 4 размеченные точки, не расшифрован |
| 730, 740, 750 | не расшифрованы |

Мобильные комплексы (тренога, ДПСмоб, МЗ) в Datakam практически отсутствуют, а те, что есть, разбросаны по разным кодам — отделить их нельзя. Около 20 % стационарных камер с сайта в Datakam отсутствуют. По умолчанию HUD использует только код 510.

## 3. Сторонний формат iGo (справка)

CSV сайта speedcamonline.ru, вариант `igoext`: `IDX,X,Y,TYPE,SPEED,DIRTYPE,DIRECTION` (X — долгота, Y — широта). Типы: 192/194 — камеры, 206 — посты ДПС, 193/199 — мобильные/треноги, 68 — не расшифрован. Направление в нём повёрнуто на 180° относительно Datakam. Конвертером пока не читается: файл с сайта обрывается на стороне сервера.
