# Формат базы камер

Описаны собственный формат `cams.bin`, который читает HUD, и исходные форматы: основной — iGo extended с сайта speedcamonline.ru, дополнительный — Datakam. Конвертер — `tools/gen_cams.py`, чтение в прошивке — `waveshare_hud_mockup/cam_alert.c`.

## 1. cams.bin (то, что лежит в FATFS как `/cams.bin`)

Little-endian, без выравнивания. Размер файла строго `16 + N·12` (OTA-страница проверяет).

### Заголовок, 16 байт

| Смещение | Тип | Значение |
|---|---|---|
| 0 | char[4] | `CAM1` — сигнатура и версия формата |
| 4 | u32 | N — число записей |
| 8 | u32 | дата базы, числом `ддммгг` (например 110926 = 11.09.26) |
| 12 | u32 | резерв, 0 |

### Запись, 12 байт

| Смещение | Тип | Значение |
|---|---|---|
| 0 | f32 | широта, ° |
| 4 | f32 | долгота, ° |
| 8 | u16 | направление камеры, ° (0..359, откуда смотрит камера по ходу контролируемого движения); `0xFFFF` — нет направления, камера работает в обе стороны |
| 10 | u8 | ограничение скорости, км/ч (0 — неизвестно; значения >255 обрезаются) |
| 11 | u8 | биты 0..3 — индекс типа; биты 4..5 — признак из исходной базы (0/1/2); биты 6..7 — 0 |

Индекс типа:

| Индекс | Что | Из iGo (TYPE) | Из Datakam (код) |
|---|---|---|---|
| 0 | стационарная камера | 192, 194 | 510 |
| 1 | не расшифрован | 68 | 530 |
| 2..7 | не камеры скорости / не расшифрованы | — | 700, 710, 720, 730, 740, 750 |
| 8 | пост ДПС | 206 | 760 |
| 9 | мобильная камера | 193 | — |
| 10 | тренога | 199 | — |
| 11 | камера полосы (автобусной) | — (7Ways+ 199) | — |
| 12 | начало средней скорости | — (7Ways+ 227) | — |
| 15 | неизвестный код | — | прочее |

В `HUD_CAM_TYPE_MASK` бит i соответствует индексу типа i (по умолчанию `0x001` — только стационарные камеры, бит 8 добавляет посты ДПС). Для iGo поле признака равно 0.

### Порядок записей

Записи отсортированы по ключу ячейки сетки 0,05° (20 ячеек на градус):

```
cy  = (int)(lat * 20)
cx  = (int)(lon * 20)
key = cy * 4096 + cx
```

Внутри ячейки порядок произвольный. Поиск: бинарный поиск первой записи с нужным ключом (`lower_bound`), затем перебор записей с этим ключом. Чтобы найти камеры вокруг машины, берутся 3×3 соседние ячейки (ячейка ≈ 5,5 км по широте, ≈ 3 км по долготе в Москве, окно оповещения ≤ 600 м). База целиком загружается в PSRAM при старте и дальше только читается.

Размер: вся Россия ≈ 185 тыс. записей ≈ 2,2 МБ; Москва и область ≈ 420 КБ.

### Как HUD использует запись

- расстояние вдоль движения > 0 и ≤ R, где R = clamp(v·12 с, 200, 600) м;
- боковое отклонение от линии движения ≤ `HUD_CAM_CROSS_M` (35 м; для уже ведомой камеры в 1,7 раза больше — гистерезис);
- если направление задано — курс машины в пределах ±`HUD_CAM_DIR_DEG` (50°) от него;
- тип проходит по маске `HUD_CAM_TYPE_MASK`; из подходящих выбирается ближайшая впереди.

## 2. Основной источник: speedcamonline.ru, iGo extended

Адрес для скачивания (без мобильных комплексов): `https://speedcamonline.ru/igoext/Rus/nomobile/`

Текстовый CSV с заголовком, разделитель запятая, одна точка в строке:

```
IDX,X,Y,TYPE,SPEED,DIRTYPE,DIRECTION
4,39.0990694,51.6482993,192,60,1,97
```

| Поле | Значение |
|---|---|
| IDX | номер записи на сайте |
| X | долгота, ° |
| Y | широта, ° |
| TYPE | 192, 194 — стационарная камера; 206 — пост ДПС; 193 — мобильная; 199 — тренога; 68 — не расшифрован (4 точки) |
| SPEED | ограничение, км/ч (0 — неизвестно) |
| DIRTYPE | в наших выгрузках всегда 1; для 0 конвертер считает, что направления нет |
| DIRECTION | направление, ° — **повёрнуто на 180°** относительно направления движения; конвертер прибавляет 180° |

Особенности:
- Выгрузка с сайта может обрываться на стороне сервера (получается файл ≈ 55–65 КБ с оборванной последней строкой). Конвертер пропускает битые строки, но обрезанный файл покрывает только часть страны (по долготе файл идёт примерно с запада на восток), поэтому лучше убедиться, что скачан весь файл.
- В основном файле есть и стационарные камеры, и посты ДПС (≈ 1182 камеры и 413 постов в имеющейся неполной выгрузке); по сравнению с Datakam покрытие стационарных камер полнее (в Datakam нет около 20 % камер с сайта).
- Даты в файле нет: конвертер берёт дату изменения файла.

### Источник: 7Ways+ extended+ (openSpeedcam.net)

Открытая база энтузиастов под навигатор 7Ways. Конвертер определяет формат автоматически (первая строка начинается с `IDX`, в данных 9 колонок):

```
IDX,X,Y,TYPE,SPEED,DirType,Direction,Distance,Angle
1,60.651221,56.805247,192,80,1,24,500,25
```

Берутся только камеры: 192, 194, 12 (скорость «сзади»), 203 (светофор + скорость) → индекс 0 (для 12 и 203 в признак пишется 1 и 2); 68 → 1; 215 (пост ДПС) → 8; 193, 209 (мобильная) → 9; 199 (камера полосы) → 11; 227 (начало средней скорости) → 12. Знаки, переходы, лежачие полицейские и пр. пропускаются. `Direction` 0 или 360 (или `DirType` 0) — без направления; `DirType` 2 — в обе стороны (пишутся две записи: курс и обратный). `Distance` и `Angle` не используются. Дата берётся из заголовка (`… 14.10.2026 …`).

Направление `Direction` в 7Ways+ повёрнуто на 180° относительно курса, с которым камера «смотрит» на проезжающих (как и в iGo-ext): `gen_cams.py` по умолчанию добавляет 180° (`--w7-dir-offset`, `W7_DIR_OFFSET`). Значения типов, кроме 192/194/215, на местности не проверены. База открытая: её ведёт сообщество энтузиастов, камеры добавляются пользователями, скачивание свободное (явного текста лицензии на сайте нет).

## 3. Дополнительный источник: Datakam (`speedcam_*.bin`)

Найден разбором файла; не документирован производителем, поэтому часть полей неизвестна. Конвертер подмешивает из него только коды 510 и 760 и только там, где в основной базе в радиусе 30 м нет записи того же типа.

### Заголовок, 68 байт

| Смещение | Значение |
|---|---|
| 0..63 | текст cp1251: `DATAKAM. MOSCOW. SPEEDCAM BASE.` / `СОЗДАН ОТ: дд.мм.гг` / пустая строка |
| 64 | u32 N — число записей |

Размер файла = `68 + N·23`.

### Запись, 23 байта

| Смещение | Тип | Значение |
|---|---|---|
| 0 | f32 | долгота |
| 4 | f32 | широта |
| 8 | u16 | код типа (510, 530, 700, 710, 720, 730, 740, 750, 760) |
| 10 | u16 | ограничение, км/ч |
| 12 | u16 | направление, ° (360 — без направления) |
| 14 | u16 | радиус оповещения, м (во всей базе 500) |
| 16 | u16 | константа 10 |
| 18 | u8 | признак 0/1/2 (смысл не установлен; переносится в cams.bin) |
| 19 | u32 | ключ сортировки Datakam; HUD не использует |

Конвертер отбрасывает записи с координатами вне 19°<lon<180°, 40°<lat<82°. Проверено по реальным логам: курс машины при проезде записи совпадает с её направлением.

### Что известно о кодах типов

Сверка с размеченным списком (≈1270 точек, совпадение до 30 м):

| Код | Что это |
|---|---|
| 510 | стационарная камера (в том числе муляжи МЛЖ, ММ, ДПСкам — идут тем же кодом) |
| 760 | пост ДПС / ДПС мобильный |
| 700, 710, 720 | не камеры скорости: объекты с короткой зоной ≈50 м, предположительно неровности / переезды (не подтверждено) |
| 530 | всего 4 размеченные точки, не расшифрован |
| 730, 740, 750 | не расшифрованы |

Мобильные комплексы (тренога, ДПСмоб, МЗ) в Datakam практически отсутствуют, а те, что есть, разбросаны по разным кодам — отделить их нельзя. Около 20 % стационарных камер с сайта в Datakam отсутствуют. По умолчанию HUD использует только код 510.
